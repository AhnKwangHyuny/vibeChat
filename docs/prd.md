# PRD: Vibe Chat (관심사 기반 실시간 채팅 플랫폼) — 7일 MVP

## 1) 제품 개요
- 비전: 같은 관심사를 가진 사람들이 “지금” 연결되어 대화를 시작할 수 있는 가장 간편한 실시간 채팅 경험을 제공한다.
- 미션: 태그로 방을 쉽게 찾고, 로그인 없이도 즉시 참여하며, 이미지/GIF/짧은 영상까지 부드럽게 주고받는 안정적인 대화 환경을 1주일 내 실행 가능한 범위로 제공한다.
- 고수준 설명:
  - 웹 반응형 기반의 실시간 채팅 서비스
  - 태그 기반 검색/발견, 공개·비공개 방 운영
  - 비로그인(게스트 닉네임) + 소셜 로그인(구글) 제공
  - 이미지/GIF/10초 이하 영상 업로드 및 표시
  - 부적절한 콘텐츠 신고 기능
  - 포트폴리오 관점에서 완성도 있는 UI/UX, 안정성, 문서화를 강조

## 2) 목표 및 목적
- 비즈니스 목표
  - 7일 내 실사용 가능한 데모(MVP) 완성
  - 포트폴리오로 제시 가능한 UI/UX의 완성도 확보
  - 안정적인 실시간 통신과 기본 안전장치(신고, 입력 검증) 제공
- 사용자 목표
  - 관심사 태그로 빠르게 채팅방을 찾고 즉시 참여
  - 로그인 없이 닉네임만으로 대화 시작 (선택적으로 소셜 로그인)
  - 이미지/GIF/짧은 영상 공유를 통한 생동감 있는 대화
- 성공 지표(측정 기준)
  - p95 메시지 전달 지연 ≤ 1초
  - 100명 동시 접속 상황에서 메시지 성공 전송률 ≥ 99%
  - 크래시·치명적 오류 없는 세션 비율 ≥ 99%
  - 첫 진입 후 “첫 메시지 전송”까지 소요시간(중간 퍼널) ≤ 60초(신규 사용자 기준)
  - 사용성 간이 테스트(5명 내외)에서 핵심 플로우(검색→입장→전송) 완료율 ≥ 80%
  - 문서화(README, 기능/화면 설명, 실행 가이드) 100% 충족

## 3) 대상 고객
- 사용자 페르소나
  - 탐색가: 관심사로 방을 발견해 가볍게 대화를 시작하고 싶은 모바일 중심 사용자
  - 개설자: 소규모 모임을 위한 공개/비공개 방을 빠르게 만들고 초대하고 싶은 사용자
  - 공유자: 이미지/GIF/짧은 영상으로 실시간 반응을 주고받고 싶은 사용자
  - 라이트 유저: 계정 생성 없이 즉시 참여하고 싶은 사용자
- 인구통계
  - SNS/메신저 사용 경험이 있는 남녀노소 전반
  - 모바일 우선 이용 경향(그러나 데스크톱 사용자도 고려)
- 주요 사용 사례
  - 태그 자동완성으로 관심사 방 검색 후 즉시 입장
  - 공개/비공개 방 생성 및 초대 링크/코드 공유
  - 텍스트/이미지/GIF/10초 이하 영상 전송·보기
  - 타이핑 중 표시, 온라인 사용자 수 확인
  - 부적절한 메시지 신고

## 4) 사용자 스토리 및 사용 사례
- 스토리 A: 게스트로 빠른 입장
  - 상황: 신규 사용자가 홈페이지 접속
  - 여정: 닉네임 입력 → 관심 태그 검색 → 방 선택 → 입장 → 첫 메시지 전송
  - 수용 기준:
    - 닉네임 미입력 시 메시지 전송 불가 안내가 표시된다.
    - 태그 입력 시 자동완성이 300ms 내 반응한다.
    - 방 입장 후 3초 내 기존 최근 메시지(최소 30개)가 보인다.
- 스토리 B: 방 생성과 초대
  - 상황: 개설자가 소규모 비공개 대화를 만들고 싶음
  - 여정: 방 생성 → 공개/비공개 선택 → 태그 지정 → 생성 완료 → 초대 링크/코드 공유
  - 수용 기준:
    - 방 생성 폼에서 필수값(제목, 공개/비공개, 최소 1개 태그) 미입력 시 생성 불가 안내
    - 비공개 방은 초대 링크/코드 없이는 입장 불가
    - 생성 직후 방 상세 화면으로 전환된다.
- 스토리 C: 미디어 포함 실시간 대화
  - 상황: 참여자가 대화 중 이미지를 공유
  - 여정: 입력창 → 이미지/GIF/영상 선택(미리보기) → 전송 → 실시간 표시
  - 수용 기준:
    - 영상 길이 > 10초 또는 파일 크기(예: 20MB 초과) 시 전송 차단 및 사유 안내
    - 미리보기에서 취소/재선택 가능
    - 업로드 중 상태(진행률 또는 로딩) 표시
- 스토리 D: 안전 장치
  - 상황: 부적절한 메시지를 발견
  - 여정: 메시지 메뉴 → 신고 → 사유 선택 → 제출 → 완료 안내
  - 수용 기준:
    - 신고는 3스텝 이내 완료 가능
    - 신고 성공/실패 결과가 즉시 안내된다.
- 스토리 E: 반응형/다크모드
  - 상황: 모바일/데스크톱 전환 및 어두운 환경 사용
  - 수용 기준:
    - 모바일/태블릿/데스크톱 3가지 주요 브레이크포인트에서 레이아웃 붕괴 없음
    - 다크모드 토글 시 200ms 내 테마 전환, 재방문 시 이전 설정 유지

## 5) 기능적 요구사항(Functional Requirements)
우선순위: P0(반드시), P1(가급적), P2(여유 시)

- FR-01 게스트 닉네임 입장(P0)
  - 닉네임 입력 후 즉시 대화 참여 가능
  - 닉네임은 방 내 중복 불가(중복 시 안내)
  - 세션 유지 중 닉네임 유지
  - 수용 기준: 중복 닉네임 시 대체 제안(숫자 suffix) 제공

- FR-02 소셜 로그인(구글)(P1)
  - 선택적으로 계정 연동하여 동일 사용자 식별
  - 수용 기준: 로그인/로그아웃 플로우 1분 내 완료, 프로필(닉네임/아바타) 반영

- FR-03 태그 기반 검색(P0)
  - 태그 자동완성, 다중 태그로 방 검색
  - 수용 기준: 검색 결과 500ms 내 최초 응답, 결과가 0개일 경우 대체 제안(유사 태그/인기 태그) 표기

- FR-04 방 목록/상세 보기(P0)
  - 공개/비공개, 참여자 수, 최근 메시지 시각 등 기본 정보 표시
  - 수용 기준: 목록에서 방 클릭 시 1초 내 상세로 이동

- FR-05 방 생성(P0)
  - 제목, 설명(선택), 공개/비공개, 태그(최소 1개) 설정
  - 비공개 방은 초대 링크/코드 자동 생성
  - 수용 기준: 생성 실패 시 필드 단위 에러 메시지 제공

- FR-06 방 참여/초대(P0)
  - 공개 방: 바로 입장
  - 비공개 방: 초대 링크/코드 필요
  - 수용 기준: 잘못된 초대 코드 시 명확한 에러와 재시도 안내

- FR-07 실시간 메시징 — 텍스트(P0)
  - 즉시 전송/수신, 전송 실패 시 재시도 옵션
  - 수용 기준: p95 전송 지연 ≤ 1초, 전송 실패 시 사용자에게 재시도/취소 선택 제공

- FR-08 실시간 메시징 — 이미지/GIF/영상(P0)
  - 이미지/GIF/10초 이하 영상 업로드·표시
  - 수용 기준: 업로드 제한(형식/크기/길이) 위반 시 전송 차단 및 사유 안내, 미리보기 제공

- FR-09 메시지 표기/형식(P0)
  - 발신자, 시각, 타입(텍스트/이미지/GIF/영상) 명확히 구분
  - 수용 기준: 장문 텍스트는 줄바꿈/말줄임 처리, 이미지/영상은 비율 유지

- FR-10 타이핑 인디케이터(P1)
  - 같은 방의 다른 참여자에게 “입력 중” 상태 표시
  - 수용 기준: 타이핑 시작/종료 이벤트 반영 지연 ≤ 1초

- FR-11 온라인 사용자 수 표시(P1)
  - 방 상단 또는 사이드에 현재 접속 수 표기
  - 수용 기준: 입장/퇴장 반영 지연 ≤ 2초

- FR-12 스크롤 및 과거 메시지 로딩(P0)
  - 최근 메시지부터 표시, 위로 스크롤 시 과거 메시지 점진적 로딩
  - 수용 기준: 최초 진입 시 최소 30개 메시지 노출, 상단 도달 시 추가 30개 로딩
  - 메시지 보관 정책: 방별 최근 1,000개까지만 유지(P0)

- FR-13 콘텐츠 신고(P0)
  - 메시지 단위 신고(사유 선택 포함)
  - 수용 기준: 신고 처리 완료 알림 제공, 중복 신고 방지

- FR-14 반응형 UI(P0)
  - 모바일/태블릿/데스크톱 화면 최적화
  - 수용 기준: 핵심 인터랙션(검색/입장/전송)이 모든 해상도에서 1초 내 반응

- FR-15 다크모드(P2)
  - 라이트/다크 테마 전환 및 설정 저장
  - 수용 기준: 테마 전환 시 깜빡임 최소화, 대비 기준 준수

- FR-16 에러/로딩 상태 표시(P1)
  - 네트워크 오류, 업로드 실패, 재시도 등의 상태를 명확히 공지
  - 수용 기준: 모든 비동기 작업에 로딩/성공/실패 상태 UI 존재

- FR-17 기본 레이트 제한(P1)
  - 단시간 과도한 메시지 전송 시 제약 및 안내
  - 수용 기준: 제한 발동 시 남은 대기시간 안내

## 6) 비기능적 요구사항(Non-Functional Requirements)
- 성능
  - p95 메시지 지연 ≤ 1초(실시간성 최우선)
  - 100명 동시 접속에서 안정적 동작(메시지 유실율 ≤ 1%)
  - 초기 화면 로드 ≤ 3초(보통 네트워크), 상호작용 지연 ≤ 100ms 수준 유지 목표
- 신뢰성/가용성
  - 전송 실패 시 재시도/복구 플로우 제공
  - 예외 발생 시 사용자 친화적 안내 및 로그 수집(데모 범위 내)
- 보안/안전
  - 사용자 입력/메시지 내용의 유해 문자 필터링 및 정제
  - 파일 업로드 검증(허용 형식/크기/길이), 악성 업로드 차단
  - 세션 위변조 방지, 기본 수준의 위조 요청 방지
  - 기본 레이트 제한으로 스팸 전송 완화
- 사용성/접근성
  - 모바일 우선, 주요 브레이크포인트 대응
  - 키보드 접근성(입력창 포커스, 전송 단축키 등) 기본 제공
  - 색 대비/명확한 피드백 제공
- 확장성(데모 범위)
  - 태그/방 목록/최근 메시지에 대한 캐시 전략으로 체감 성능 유지(구체 기술 명시 없음)
- 데이터/정책
  - 메시지 보관: 방별 최근 1,000개까지
  - 미디어 정책: 이미지/GIF/영상(≤10초, 크기 제한)만 허용
  - 로그/신고 기록은 데모 평가와 개선을 위한 최소한 범위로 유지

## 7) 성공 지표(KPI/분석/측정)
- 실시간 품질: p95 지연 ≤ 1초, 메시지 성공률 ≥ 99%
- 사용성: 첫 방문→첫 메시지까지 ≤ 60초(신규), 핵심 플로우 성공률 ≥ 80%
- 안정성: 크래시·치명적 오류 없는 세션 ≥ 99%
- 미디어: 업로드 성공률 ≥ 95%, 제한 위반 시 명확한 안내율 100%
- 품질 지표: README/기능 설명/실행 가이드 100% 완료, 데모 영상 제공
- 참여 지표(데모 기준): 1방당 평균 체류 ≥ 3분, 평균 전송 메시지 ≥ 5건

## 8) 일정 및 마일스톤(7일, 1인 개발)
- Day 1: 프로젝트 셋업/기본 구조 확립
  - 산출물: 화면 골격(헤더/검색/방목록), 데이터 모델 정의, 더미 데이터
  - 게이트: 기본 화면 라우팅, 더미 방 목록 노출
- Day 2: 방/태그 도메인 및 검색 플로우
  - 산출물: 방 생성/조회, 태그 검색(자동완성 포함), 공개/비공개 속성
  - 게이트: 태그로 방 검색→상세 보기까지 플로우 완료
- Day 3: 실시간 대화 기본
  - 산출물: 입장/퇴장, 텍스트 메시지 전송/수신, 기본 오류 처리
  - 게이트: 두 브라우저 간 실시간 텍스트 송수신 성공(p95 ≤ 1s)
- Day 4: UX 기본기
  - 산출물: 반응형 레이아웃, 닉네임 입력, 방 생성 모달, 상태관리/서비스 계층
  - 게이트: 게스트 닉네임 → 방 생성 → 입장 → 메시지 전송의 단일 사용자 여정 완성
- Day 5: 실시간 고도화
  - 산출물: 메시지 리스트/입력창, 타이핑 표시(P1), 온라인 사용자 수(P1), 재시도 로직, 자동 스크롤
  - 게이트: 타이핑/온라인 표시가 1초 내 반영, 실패 후 재전송 동작 확인
- Day 6: 미디어 업로드
  - 산출물: 이미지/GIF/≤10초 영상 업로드, 미리보기, 파일 검증, 썸네일/리사이즈 정책, 오류/토스트
  - 게이트: 10초 초과/크기 초과 차단 및 명확한 안내, 업로드 성공률 ≥ 95%
- Day 7: 마감/품질
  - 산출물: 다크모드(P2), 로딩/스켈레톤, 404/에러 화면, 성능 미세 최적화, README, 기능 문서, 데모 영상 스크립트
  - 게이트: 문서화 100%, 핵심 KPI 체크(p95 ≤ 1s), 데모 시나리오 무리 없이 수행

## 9) 우선순위 정리
- P0(반드시): 게스트 닉네임, 태그 검색/자동완성, 방 생성/참여(공개/비공개+초대), 텍스트/이미지/GIF/≤10초 영상 전송, 실시간 송수신, 메시지 보관(1,000개), 반응형 UI, 콘텐츠 신고, 스크롤/과거 로딩, 에러/로딩 상태, 안정성 지표 충족
- P1(가급적): 소셜 로그인(구글), 타이핑 인디케이터, 온라인 사용자 수, 메시지 재시도/복구, 레이트 제한, 스켈레톤/로딩 UX
- P2(여유 시): 다크모드, 드래그앤드롭 업로드, GIF 특화 옵션/뷰어 개선, 추천/발견 고도화

## 10) 위험요소 및 가정사항
- 위험요소
  - 1인/7일 일정 압박으로 기능 과잉 범위 위험
  - 실시간 처리와 미디어 업로드 병행 시 성능/안정성 저하 가능
  - 다양한 단말·브라우저에서의 반응형 이슈
  - 신고만으로는 충분한 모더레이션 부재(오탐/악용 가능)
- 대응/완화
  - P0 범위 고수, 지연 발생 시 P1·P2 과감한 감축
  - 영상 길이/용량 제한 강화, 실패 시 재시도·명확한 안내
  - 핵심 브레이크포인트 우선(모바일/데스크톱), 테스트 기기 축소
  - 신고 접수만 제공, 사후 조치(차단/삭제)는 데모 내 최소화
- 가정사항
  - 로컬 데모 환경에서의 시연(실배포 아님)
  - 인증/보안은 기본 수준만(데모 목적)
  - 100명 동시 접속 기준으로 성능 목표 수립
  - 추천 시스템은 MVP 범위 밖(태그 검색 중심)
  - 데이터 보존은 데모 평가 목적의 최소 범위
