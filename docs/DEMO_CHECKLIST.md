# DEMO_CHECKLIST.md: 바이브 챗 데모 체크리스트

이 문서는 제품 요구사항 문서(PRD) 및 기술 요구사항 문서(TRD)를 기반으로 바이브 챗 MVP를 시연하기 위한 주요 시나리오 및 검증 기준을 설명합니다.

## 1. 전체 목표 (PRD에서 발췌)

- 7일 이내에 사용 가능한 데모(MVP)를 완성합니다.
- 포트폴리오에 적합한 UI/UX 완성도를 확보합니다.
- 안정적인 실시간 통신 및 기본 안전 기능을 제공합니다.

## 2. 핵심 성과 지표 (KPI) (PRD에서 발췌)

- p95 메시지 전달 지연 ≤ 1초
- 100명 동시 접속 시 메시지 성공률 ≥ 99%
- 크래시/치명적 오류 없는 세션 비율 ≥ 99%
- 첫 메시지까지 소요 시간(신규 사용자) ≤ 60초
- 핵심 흐름(검색 → 참여 → 전송) 완료율 ≥ 80% (사용성 테스트)
- 문서화(README, 기능/화면 설명, 실행 가이드) 100% 완료

## 3. 데모 시나리오 (TRD에서 발췌)

이 시나리오들은 핵심 P0 기능을 다루며, 수동 또는 스크립트를 통해 테스트해야 합니다.

### 시나리오 A: 빠른 게스트 입장

- **설명:** 새로운 사용자가 게스트로 빠르게 채팅방에 입장합니다.
- **단계:**
  1.  홈페이지(`http://localhost`)에 접속합니다.
  2.  모달에 닉네임을 입력하고 "채팅 시작"을 클릭합니다.
  3.  검색창에 태그(예: "test")를 입력하고 Enter를 누릅니다.
  4.  검색 결과에서 공개 채팅방을 선택하고 "방 참여"를 클릭합니다.
  5.  채팅방에서 텍스트 메시지를 보냅니다.
- **검증:**
  - 첫 방문 시 닉네임 모달이 나타납니다.
  - 닉네임이 성공적으로 설정되고 사용자가 인증됩니다(세션 생성).
  - 태그 자동 완성이 작동합니다(구현된 경우).
  - 채팅방 검색 결과가 표시됩니다.
  - 사용자가 채팅방에 성공적으로 참여합니다.
  - 텍스트 메시지가 1초 이내에 다른 연결된 클라이언트(있는 경우)에 의해 전송되고 수신됩니다.

### 시나리오 B: 방 생성 및 초대

- **설명:** 사용자가 비공개 채팅방을 만들고 다른 사람들을 초대합니다.
- **단계:**
  1.  인증되었는지 확인합니다(게스트 또는 로그인).
  2.  "방 만들기" 페이지(예: `/create`)로 이동합니다.
  3.  방 제목, 설명(선택 사항)을 입력합니다.
  4.  "비공개 방" 체크박스를 선택합니다.
  5.  최소 하나의 태그를 추가합니다.
  6.  "방 만들기"를 클릭합니다.
  7.  생성된 초대 코드를 복사합니다.
  8.  다른 브라우저/시크릿 창을 엽니다.
  9.  홈페이지에 접속하여 다른 닉네임을 입력합니다.
  10. 초대 코드를 사용하여 비공개 채팅방에 참여를 시도합니다.
- **검증:**
  - 채팅방이 성공적으로 생성됩니다.
  - 비공개 채팅방에 대한 초대 코드가 생성됩니다.
  - 다른 사용자는 올바른 초대 코드 없이는 참여할 수 없습니다.
  - 사용자가 초대 코드를 사용하여 비공개 채팅방에 성공적으로 참여합니다.

### 시나리오 C: 미디어 풍부한 실시간 대화

- **설명:** 참가자들이 대화에서 이미지, GIF, 짧은 비디오를 공유합니다.
- **단계:**
  1.  기존 채팅방에 참여합니다(예: 시나리오 A에서).
  2.  "첨부" 버튼을 클릭합니다.
  3.  이미지 파일(JPG, PNG, WEBP)을 선택합니다.
  4.  미리보기가 표시되는지 확인합니다.
  5.  "업로드 및 전송"을 클릭합니다.
  6.  GIF 파일에 대해 반복합니다.
  7.  짧은 MP4 비디오 파일(10초 미만)에 대해 반복합니다.
- **검증:**
  - 이미지, GIF, 비디오 파일이 성공적으로 업로드되고 채팅에 표시됩니다.
  - 크기/길이 제한을 초과하는 파일은 명확한 오류 메시지와 함께 거부됩니다.
  - 미디어 메시지가 다른 클라이언트에 실시간으로 수신됩니다.

### 시나리오 D: 안전 메커니즘 (신고)

- **설명:** 사용자가 부적절한 메시지를 신고합니다.
- **단계:**
  1.  채팅방에서 메시지에 마우스를 올리면 옵션이 나타납니다.
  2.  "신고" 옵션을 클릭합니다.
  3.  사유(예: SPAM, ABUSE, NSFW, OTHER)를 선택합니다.
  4.  선택적 세부 정보를 추가합니다.
  5.  "신고 제출"을 클릭합니다.
- **검증:**
  - 신고 인터페이스에 접근할 수 있습니다.
  - 신고가 성공적으로 제출됩니다(토스트 알림).
  - 동일한 사용자가 동일한 메시지에 대해 중복 신고하는 것이 방지됩니다.

## 4. 검증 체크리스트 (완료 기준) (TRD에서 발췌)

- **기능 (P0):**
  - 게스트 닉네임 입력, 방 생성/참여(공개/비공개), 태그 검색, 텍스트/이미지/GIF/≤10초 비디오 전송, 실시간 송수신, 신고, 반응형 UI, 메시지 보존(1,000개), 스크롤/이전 기록 로딩.
- **비기능:**
  - 100명 동시 접속: 메시지 성공률 ≥ 99%, p95 지연 ≤ 1초.
  - 첫 메시지까지 소요 시간 ≤ 60초.
  - 로깅/문서화 완료(Swagger + README).
- **보안:**
  - XSS/CSRF 방어, 파일 유효성 검사, 레이트 제한 작동.
- **배포 (로컬):**
  - `docker-compose up`으로 단일 명령 데모 가능.
