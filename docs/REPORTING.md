# REPORTING.md: 바이브 챗 메시지 신고

이 문서는 제품 요구사항 문서(PRD) 및 기술 요구사항 문서(TRD)를 기반으로 바이브 챗 애플리케이션의 메시지 신고 프로세스 및 정책을 설명합니다.

## 1. 목적

사용자에게 채팅 메시지 내 부적절하거나 유해한 콘텐츠를 신고할 수 있는 메커니즘을 제공하여, 더 안전하고 긍정적인 채팅 환경을 보장합니다.

## 2. 사용자 스토리 및 사용 사례 (PRD에서 발췌)

- **스토리 D: 안전 메커니즘**
  - **상황:** 참가자가 부적절한 메시지를 발견합니다.
  - **여정:** 메시지 메뉴 → 신고 → 사유 선택 → 제출 → 완료 알림.
  - **수용 기준:**
    - 신고는 3단계 이내로 완료할 수 있습니다.
    - 신고의 성공/실패 결과가 즉시 통지됩니다.

## 3. 기능 요구사항 (PRD에서 발췌)

- **FR-13 콘텐츠 신고 (P0)**
  - 메시지 단위 신고 (사유 선택 포함).
  - **수용 기준:** 신고 처리 완료 알림 제공, 중복 신고 방지.

## 4. API 명세 (TRD에서 발췌)

### `POST /api/messages/{messageId}/report`

부적절한 콘텐츠에 대해 특정 메시지를 신고합니다.

- **경로 매개변수:**
  - `messageId`: `number` (신고할 메시지 ID)
- **요청 본문:**
  ```json
  {
    "reason": "SPAM" | "ABUSE" | "NSFW" | "OTHER",
    "details": "string (선택 사항)"
  }
  ```
- **응답 (201 Created):** 빈 본문.
- **오류 (404 Not Found):** 메시지를 찾을 수 없습니다.
- **오류 (409 Conflict):** 이 사용자가 이미 이 메시지를 신고했습니다.

## 5. 비즈니스 로직 규칙 (TRD에서 발췌)

- **신고:** 동일한 사용자가 동일한 메시지에 대해 중복 신고하는 것을 방지합니다. 감사 로그를 기록합니다.

## 6. 레이트 제한 (TRD에서 발췌)

- **신고 제출:** 사용자/IP당 분당 5회.
- **응답:** 429 Too Many Requests (요청 과다)와 `retryAfterSeconds` 헤더.

## 7. 구현 세부 사항

- **백엔드:**
  - `ReportController.java`: `POST /api/messages/{messageId}/report` 엔드포인트를 처리합니다.
  - `ReportService.java`: 신고 저장, 중복 확인, 감사 로깅 로직을 포함합니다.
  - `MessageReport` 엔티티 및 `MessageReportRepository`를 통한 영속성.
- **프론트엔드:**
  - 메시지를 선택하고 신고를 시작하는 UI.
  - 사유 선택 및 선택적 세부 정보를 추가하는 폼.
  - 성공/실패 알림 표시.
  - 레이트 제한 응답 처리 (예: 신고 버튼 일시적으로 비활성화).

## 8. 중재 (데모 범위)

- MVP/데모의 경우, 시스템은 주로 신고 수집에 중점을 둡니다. 자동 또는 수동 중재 조치(예: 메시지 삭제, 사용자 차단)는 이 MVP의 범위를 벗어나지만, 향후 반복에서 통합될 수 있습니다.
- 평가 및 개선을 위해 신고 감사 로그가 유지됩니다.
